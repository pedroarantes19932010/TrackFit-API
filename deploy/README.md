# Subir o piloto conectado

O APK offline serve para conhecer as telas. Para que dois aparelhos compartilhem fichas, escolha uma máquina com Docker e um domínio cujo DNS aponte para ela. Libere as portas 80 e 443. Não há hospedagem ou conta de fornecedor provisionada por este repositório.

1. Na pasta deploy, copie env.example para .env e preencha TRACKFIT_DOMAIN. Crie a pasta secrets. Comece com TRACKFIT_PROVIDER=demo para testar sem consumo da API de IA.
2. Rode `docker compose up -d --build` e confira `https://SEU-DOMINIO/health`. Rode `docker compose exec api python -m server.bootstrap --name Pedro` para criar o acesso inicial. Guarde o código em privado.
3. Abra o Android, informe o endereço HTTPS e entre como treinador. Cadastre um aluno fictício e crie seu modelo em **Modelos**. Revise os dias, exercícios e o perfil antes de aprovar. O aluno usa o próprio código no outro aparelho.
4. Para testar a IA externa, configure OPENAI_API_KEY, OPENAI_MODEL (modelo da sua conta compatível com Responses e saída estruturada) e TRACKFIT_PROVIDER=openai no ambiente privado do servidor. Reinicie com `docker compose up -d`. Envie uma avaliação elegível e confira o resultado e o consumo no painel do provedor. Cada aluno tem limite de cinco tentativas por hora. Configure também seu limite de gastos na conta do provedor.
5. Para os avisos, registre o aplicativo Android br.com.trackfit.piloto no seu projeto Firebase. Coloque o arquivo de configuração cliente google-services.json em android/app/ e compile o APK dessa configuração no Android Studio. A chave privada de serviço pertence somente ao servidor. Prefira identidade da plataforma via Application Default Credentials. Se usar arquivo, monte deploy/secrets/firebase.json com acesso de leitura apenas para o processo necessário (UID 10001 no contêiner). Ative a API Firebase Cloud Messaging, dê ao serviço permissão de envio e configure TRACKFIT_PUSH=fcm e TRACKFIT_FIREBASE_PROJECT na mesma instância. Recrie o serviço. O teste em CI usa APK sem configuração de uma conta Firebase.
6. No aparelho do treinador, permita notificações e escolha **Avisos → Ativar avisos com o app fechado**. Leve o aplicativo para segundo plano. No outro aparelho, gere uma ficha completa. Deve chegar um aviso genérico. O detalhe exige login. O Android pode adiar a entrega conforme rede, permissão e estado do sistema. Forçar parada do aplicativo nas configurações é diferente de simplesmente fechar a tela.
7. Em **Consultar histórico completo**, confira a ficha v1, as revisões de planos e o que foi realizado. As tabelas originais permanecem intactas. O histórico offline é uma simulação em memória. O histórico conectado lê todas as versões autorizadas no mesmo banco. Bancos antigos em arquivos físicos distintos exigem conciliação de identidades antes de importação.
8. Para testar o backup, rode `docker compose exec api python -m server.backup /data/trackfit.sqlite3 /data/copia-teste.sqlite3` e `docker compose cp api:/data/copia-teste.sqlite3 ./secrets/copia-teste.sqlite3`. Guarde uma cópia protegida fora do servidor. Para conferir a restauração, abra a cópia em outra instância com TRACKFIT_DB apontando para ela e faça login com um código de teste ainda válido.

O servidor conserva o aviso na caixa do treinador se o envio falhar. A fila usa tentativas com intervalo crescente e expira após 24 horas. O vínculo do aparelho expira junto com o acesso. Se o aparelho for reinstalado ou trocar de acesso, ative os avisos novamente. A assinatura do APK de demonstração é de teste. Use assinatura privativa estável para distribuição e atualizações de produção.

## Recuperar o acesso do treinador

Se o código do treinador do piloto vencer ou for perdido, o administrador do servidor pode executar `docker compose exec api python -m server.bootstrap --renew` na pasta deploy. O comando mostra um novo código válido por 30 dias no terminal privado. Entre com ele e reative os avisos em **Avisos**. Os códigos anteriores do treinador perdem a validade. Os alunos mantêm seus códigos, vínculos e treinos. A operação se aplica à instalação com um único treinador do piloto autenticado por código.
